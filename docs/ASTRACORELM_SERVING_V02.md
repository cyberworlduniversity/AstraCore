# AstraCoreLM v0.2 serving contract

This service connects the independently trained Python/PyTorch AstraCoreLM v0.2 checkpoint to the Node.js AstraCore API. It is deliberately separate from the Vercel web deployment.

## Required files

The checkpoint directory must contain the outputs from the same completed training and evaluation run:

- `checkpoint.pt`
- `tokenizer.json`
- `model-config.json`
- `behavioral_evaluation.json`

The loader verifies the checkpoint's embedded tokenizer/config hashes and verifies the evaluation report references the exact checkpoint and tokenizer hashes.

## Local experimental smoke test

Experimental mode is permitted only on loopback. It is not production approval and cannot bind to a public interface.

```bash
export ASTRACORE_LM_HOST=127.0.0.1
export ASTRACORE_LM_PORT=8790
export ASTRACORE_LM_CHECKPOINT=artifacts/astracore-lm-v0.2
export ASTRACORE_LM_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(40))')"
export ASTRACORE_LM_ALLOW_EXPERIMENTAL=1
python scripts/serve_lm_v02.py
```

Both `GET /health` and `POST /v1/generate` require the bearer token. Experimental runtime responses always report `production_approved: false`.

## Production approval

Production mode has no automatic approval path. A reviewer must create a separate approval JSON file after examining the actual test and behavioral evaluation evidence. It must contain:

```json
{
  "production_approved": true,
  "checkpoint_sha256": "<exact SHA-256 of checkpoint.pt>",
  "tokenizer_sha256": "<exact SHA-256 of tokenizer.json>",
  "evaluation_sha256": "<exact SHA-256 of behavioral_evaluation.json>",
  "approved_by": "<reviewer identity>",
  "approved_at": "<UTC ISO-8601 timestamp>"
}
```

Do not copy example values. Compute all hashes from the final immutable artifacts. Changing any artifact invalidates the approval. The approval file must be separately reviewed and must not be generated by training or CI.

For production, set `ASTRACORE_LM_APPROVAL_FILE` to that manifest, bind behind a TLS-terminating reverse proxy, enforce network ACLs/rate limits/request limits, and do not expose the plain HTTP inference port directly to the public internet. Do not set `ASTRACORE_LM_ALLOW_EXPERIMENTAL`.

## Node.js API connection

Configure these secrets on the AstraCore Node.js host (for Vercel, use server-side Production environment variables only):

- `ASTRACORE_LM_URL`: HTTPS origin of the private Python runtime, no path/query/fragment.
- `ASTRACORE_LM_TOKEN`: same bearer token as the Python runtime.
- `ASTRACORE_LM_APPROVED_CHECKPOINT_SHA256`: exact approved checkpoint SHA-256.

The Node client refuses non-HTTPS remote URLs, incomplete configuration, experimental health responses, mismatched model versions, or checkpoint hash mismatches. When configured but unverified, `POST /api/chat` fails closed rather than falling back to a different model.

## Important limitation

A passing web deployment is not proof that this Python model runtime is deployed. The Python service needs a separately managed compute host and access to the approved checkpoint volume. The current work adds the serving code and integration contract; it does not deploy a model host, create an approval manifest, or open the production gate.
